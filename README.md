# 📺 PlayZ TV Auto-Updated Playlist

Auto-updating IPTV playlist for **PlayZ TV** app — generated by GitHub Actions every hour, with **live stream verification** so dead links are filtered out automatically.

## 🎯 What This Repo Does

1. **Fetches** the live API URL from PlayZ TV's Firebase Remote Config
2. **Decrypts** the app's encrypted config files (`app.txt`, `events.txt`, `categories.txt`, `sports.txt`)
3. **Extracts** all live + upcoming sports events with stream URLs
4. **Verifies** each stream by actually trying to fetch it (HLS master/variant/segment check, DASH MPD validation, HTTP HEAD)
5. **Generates** multiple M3U playlist variants
6. **Commits** the updated playlists back to this repo every hour
7. **Cleans up** old workflow runs to keep the repo tidy

No PAT (Personal Access Token) needed — uses the auto-injected `GITHUB_TOKEN` with `contents: write` permission.

## 🚀 Quick Setup (5 minutes)

### Step 1: Create the repo

1. Go to https://github.com/new
2. Repository name: `playztv-playlist` (or any name)
3. Set to **Public** (so raw URLs work without auth)
4. **Don't** initialize with README (we'll push our own files)
5. Click **Create repository**

### Step 2: Push the files

```bash
# Clone this repo locally (replace YOUR_USERNAME)
git clone https://github.com/YOUR_USERNAME/playztv-playlist.git
cd playztv-playlist

# Copy all files from this folder into the repo
# (or download as ZIP and extract here)

# Commit and push
git add .
git commit -m "Initial commit — PlayZ TV auto-update playlist"
git push
```

### Step 3: Enable GitHub Actions

1. Go to your repo → **Settings** → **Actions** → **General**
2. Under **Workflow permissions**, select **Read and write permissions**
3. Check ✅ **Allow GitHub Actions to create and approve pull requests**
4. Click **Save**

### Step 4: Trigger the first run

1. Go to **Actions** tab → **Update PlayZ TV Playlist** workflow
2. Click **Run workflow** → **Run workflow** (manual trigger)
3. Wait ~1 minute, refresh — you should see green ✓
4. Check `output/` folder — playlists will be there

### Step 5: Use the playlist URLs

In Televizo (or VLC, MX Player, etc.), add playlist URL:

```
https://raw.githubusercontent.com/YOUR_USERNAME/playztv-playlist/main/output/playztv_hls_only.m3u
```

Replace `YOUR_USERNAME` and `playztv-playlist` with your actual repo.

The playlist will auto-update every hour — no need to refresh in Televizo (it'll pull the latest on app restart, or you can configure Televizo to refresh periodically).

## ⚙️ How It Works

### Encryption Pipeline (reverse-engineered from APK)

PlayZ TV uses a multi-layer encryption scheme to hide its config files:

```
Raw text file
   ↓ Char substitution cipher (AbstractC3751a.m8614b)
   ↓ Base64 decode
   ↓ Base64 decode (double-encoded!)
   ↓ AES-CBC decrypt (Key1/IV1)
   = JSON config
```

The `app.txt` config uses a simpler scheme (direct base64 + AES Key2/IV2). All keys and IVs were extracted from the APK's `pa/C3262f.java` class.

### Stream Verification

Each stream URL goes through verification:

| Stream type | Verification |
|------------|--------------|
| **HLS** (`.m3u8`) | Fetch playlist → check `#EXTM3U` → if master playlist, fetch first variant → optionally HEAD-check first `.ts` segment |
| **DASH** (`.mpd`) | Fetch MPD → validate XML contains `<MPD>` root element |
| **HTTP stream** | HEAD request → check 2xx/3xx status |

Streams are verified **in parallel** (8 workers) to keep total time under 60 seconds.

### Anti-Blocking

- **Rotating User-Agents** — pool of 5 realistic mobile/desktop UAs
- **Jitter delays** — 0.2–0.8 sec between requests
- **Retry with backoff** — 3 retries, exponential backoff + jitter
- **SSL verification disabled** — some streams have bad certs but still work
- **Referer/Origin headers** — passed through from stream URL's `|referer=...&origin=...` suffix
- **Concurrent but bounded** — max 8 parallel requests to avoid hammering

## ⏰ Schedule Customization

The workflow runs every hour by default. To change:

Edit `.github/workflows/update-playlist.yml`:

```yaml
on:
  schedule:
    - cron: '0 * * * *'        # Every hour (default)
    # - cron: '0 */2 * * *'    # Every 2 hours
    # - cron: '0 */6 * * *'    # Every 6 hours
    # - cron: '*/30 * * * *'   # Every 30 minutes
```

**Note:** GitHub Actions cron is best-effort — during high load, runs may be delayed by 5–15 minutes. For strict timing, consider a self-hosted runner or external cron service triggering `workflow_dispatch`.

## 🔄 Updating the API Keys (if PlayZ TV changes them)

The encryption keys are baked into the APK. If PlayZ TV releases a new APK version with different keys:

1. Download the new APK from https://playztv-apk.pages.dev/playztv.apk
2. Decompile with jadx: `jadx --output-dir out playztv.apk`
3. Find new keys in `sources/pa/C3262f.java` (look for `SecretKeySpec(new byte[]{...})`)
4. Update `KEY1`, `IV1`, `KEY2`, `IV2` in `scripts/playztv_auto_update.py`
5. Find new char-substitution table in `sources/p244rc/AbstractC3751a.java` (f15463a and f15464b arrays)
6. Update `SRC` and `DST` constants in the script

The Firebase project ID (`playz-tv`) and API key are unlikely to change.

## ⚠️ Known Limitations

1. **DASH streams with DRM** (Widevine/ClearKey) — VLC and most players can't decrypt these. They're included in `playztv_master.m3u` but skipped in `playztv_hls_only.m3u`. The DRM KID/KEY is preserved in the M3U as a comment for advanced users.

2. **Geoblocked streams** — Some streams only work from specific countries (India, Bangladesh, etc.). The verifier runs from GitHub's servers (US/EU), so geoblocked streams may show as "failed" but actually work in your region. Use `playztv_master.m3u` to get all streams unfiltered.

3. **Time-sensitive streams** — Live event streams may not exist until ~30 minutes before kickoff. The hourly cron catches most updates, but very last-minute additions may take an hour to appear.

4. **GitHub Actions load** — During peak GitHub usage, the cron may be delayed by 5–15 minutes.
